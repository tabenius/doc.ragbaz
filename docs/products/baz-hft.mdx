## Architecture

```
Market Data Feed  (tick / bar / trade)
      │
      ▼
BAZ.HFT Ingestion Pipeline
      │   normalize · validate · timestamp
      ▼
Indicator Compute Graph  (deterministic, typed)
      │   SMA / EMA / VWAP / Bollinger / ATR / RSI / MACD / Stoch / CCI / WR
      ▼
Signal Generator  (rule-based, composable)
      │   crossing · threshold · divergence · regime
      ▼
Signal Bus  (membrane-typed event stream)
      │
      ├── Execution Layer  (order management, risk checks)
      ├── BAZ.Luna         (cycle phase detection)
      └── BAZ.Palantir     (intelligence dashboard)
```

<Admonition type="tip" title="DETERMINISM GUARANTEE">
Every indicator in BAZ.HFT produces identical output given identical input — no
floating-point non-determinism, no clock dependency. Pipelines compile to WASM
components and are verified against a Gleam reference oracle (same approach as
Glither's conformance suite).
</Admonition>

## DSL Syntax

BAZ.HFT uses a declarative signal DSL built on the Glither comprehension syntax. A signal
rule is a typed comprehension over a bar stream:

```glither
#pragma dialect baz.hft ; fold accumulate

indicator rsi14 = RSI(close, period=14)
indicator macd  = MACD(close, fast=12, slow=26, signal=9)
indicator bb20  = Bollinger(close, period=20, sigma=2.0)

group trending = bars
  | EMA(close, 20) > EMA(close, 50)

rule long_entry =
  bar
  | bar in trending                              // trend filter
  | rsi14 < 35                                   // oversold
  | macd.histogram crosses_above 0              // momentum confirms
  | close > bb20.lower                          // not below band
  => signal BUY into open_position
     on fill         into filled
     after 4 bars    into expired

rule long_exit =
  bar in open_position
  | rsi14 > 70                                  // overbought
  => signal SELL into closed_position
```

### Semantic rules

| Predicate | Semantics |
|---|---|
| `crosses_above <val>` | Previous bar below, current bar above `val` |
| `crosses_below <val>` | Previous bar above, current bar below `val` |
| `diverges_from <indicator>` | Price direction and indicator direction disagree over last n bars |
| `bar in <group>` | Bar satisfies the group's selector predicates |
| `after <n> bars` | Liveness deadline — signal expires after n bars without fill |

<Admonition type="note" title="TYPED SIGNALS">
Every signal is typed by its terminal state (`open_position`, `filled`, `expired`,
`closed_position`). The BAZ.HFT runtime enforces that every `BUY` is eventually
settled — an un-filled open position is a liveness violation surfaced as a lint
at compile time.
</Admonition>

## Optimizations

### Incremental computation

Indicators are **incremental** — on each new bar, only the delta is recomputed:

| Indicator | Incremental form | Complexity |
|---|---|---|
| SMA(n) | Sum window: add new, drop oldest | O(1) |
| EMA(n) | prev_ema × (1-k) + price × k | O(1) |
| RSI(n) | Wilder smoothing on avg gain/loss | O(1) |
| Stochastic(k, d) | Sliding H/L window | O(1) amortized |
| ATR(n) | EMA of true range | O(1) |
| MACD | Three cascaded EMAs | O(1) |

### Compile-time selector pushdown

The Glither compiler infers **cheap selectors** from crossing-guard predicates. In
the example above, `| bar in trending` and `| rsi14 < 35` are pushed into an
indexed pre-filter before the more expensive `crosses_above` check — identical to
the SQL optimiser pattern in the core spec.

### SIMD batch evaluation

For bulk backtesting, BAZ.HFT compiles indicator compute graphs to WASM SIMD
instructions (`v128` operations). A 10-year daily bar series computes all
indicators in < 40ms on a single core.
