## Architecture

```
Signal Bus  (BAZ.HFT · BAZ.Luna · Glither verdicts · infra telemetry)
      │   typed membrane exports
      ▼
BAZ.Palantir Ingestor
      │   schema validation · normalization · time-alignment
      ▼
Intelligence Layer
      │
      ├── Query Engine    (BAZ.PQL — composable signal query language)
      ├── Aggregations    (windowed reduce, cross-stream join, percentiles)
      ├── Alert Rules     (threshold · anomaly · divergence triggers)
      └── Dashboard State (reactive, persisted per-tenant)
             │
             ▼
Presentation Layer
      │
      ├── Live Dashboard  (React panels, responsive grid)
      ├── Report Renderer (PDF via WeasyPrint / diabaz themes)
      └── MCP Export      (structured data for downstream agents)
```

<Admonition type="tip" title="CAPABILITY ISOLATION">
BAZ.Palantir reads from signal streams via WIT imports — it cannot reach into source
components, only consume what they explicitly export. A rogue query cannot exfiltrate
data that producers haven't surfaced. The same capability sandbox as Glither, applied
to the analytics layer.
</Admonition>

## Query Language: BAZ.PQL

BAZ.Palantir uses **BAZ.PQL** (Palantir Query Language) — a composable, time-aware
query language for signal streams. It is an extension of the Glither comprehension
surface adapted for aggregation over time windows:

```pql
-- Current RSI regime distribution (last 30 days)
SELECT
  CASE
    WHEN rsi14 > 70 THEN 'overbought'
    WHEN rsi14 < 30 THEN 'oversold'
    ELSE 'neutral'
  END AS regime,
  COUNT(*) AS bars,
  AVG(next_bar_return) AS avg_forward_return
FROM baz.hft.indicators
WHERE source = 'BAZ/USD'
  AND timestamp > NOW() - INTERVAL '30 days'
GROUP BY regime
ORDER BY avg_forward_return DESC

-- Phase-conditioned signal accuracy (BAZ.Luna × BAZ.HFT join)
SELECT
  luna.intraday.phase_bucket(8) AS phase_octant,
  hft.signal,
  COUNT(*) AS occurrences,
  AVG(fill_return_1h) AS avg_1h_return,
  STDDEV(fill_return_1h) AS volatility
FROM baz.hft.signals
JOIN baz.luna.phases ON timestamp = luna.timestamp
WHERE hft.signal IN ('BUY', 'SELL')
  AND luna.intraday.confidence > 0.7
GROUP BY phase_octant, hft.signal
HAVING COUNT(*) > 20
ORDER BY phase_octant, hft.signal
```

### PQL syntax elements

| Construct | Semantics |
|---|---|
| `WINDOW(n bars)` | Rolling window aggregation over last n bars |
| `WINDOW(n hours)` | Rolling window by wall-clock time |
| `ALIGN ON cycle` | Resample to cycle boundaries (BAZ.Luna integration) |
| `JOIN ON timestamp` | Time-aligned join between two signal streams |
| `PERCENTILE(n, expr)` | Approximate percentile (t-digest) |
| `ANOMALY(expr, sigma)` | True if expr deviates > sigma standard deviations from rolling mean |
| `DIVERGE(a, b, n)` | True if series a and b have opposite sign over last n periods |
| `CROSSOVER(a, b)` | True at bars where a crosses above b |

## Semantics

### Signal type system

All signals in BAZ.Palantir are **typed** by their source membrane's WIT export
signature. The type system prevents dashboard configuration from connecting
incompatible signals:

```wit
// BAZ.HFT WIT export — indicator values
interface hft-indicators {
  record indicator-value {
    name: string,
    period: u32,
    value: f64,
    timestamp: u64,
    confidence: f32,    // [0, 1]
  }
  get-indicator: func(source: string, name: string) -> option<indicator-value>
  subscribe-stream: func(source: string, names: list<string>) -> stream<indicator-value>
}

// BAZ.Luna WIT export — phase signals
interface luna-phases {
  record phase-signal {
    cycle-name: string,
    phase: f32,         // [0, 2π]
    amplitude: f32,     // relative to 90d mean
    confidence: f32,    // [0, 1]
    timestamp: u64,
  }
  subscribe-cycle: func(cycle-name: string) -> stream<phase-signal>
}
```

The BAZ.PQL type checker validates at query compile time that all JOINed streams
export compatible timestamp types and that aggregation functions are applied to
numerically-typed fields.

### Alert semantics

Alerts in BAZ.Palantir follow the Glither liveness model:

- Every alert has a **terminal state** (`triggered`, `cleared`, `expired`)  
- Every `triggered` alert must eventually reach `cleared` or `expired` — a liveness obligation
- Alerts without a deadline are flagged by the `baz.palantir` lint at dashboard save time
- Alert history is append-only and content-addressed — no retrograde modification
