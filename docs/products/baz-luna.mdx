## Architecture

```
Observation Stream  (price ticks, system metrics, any scalar series)
      │
      ▼
BAZ.Luna Decomposer
      │   detrend · segment · FFT / autocorrelation
      ▼
Cycle Catalog       (named, typed, versioned cycles)
      │
      ├── Phase Estimator   (current phase ∈ [0, 2π], confidence)
      ├── Amplitude Tracker (cycle strength, fade / amplify)
      └── Harmonic Detector (sub-cycles, overtones)
             │
             ▼
Phase Signal Bus  (membrane-typed phase events)
      │
      ├── BAZ.HFT  (phase as filter condition in signal rules)
      ├── BAZ.Palantir  (cycle dashboard)
      └── Glither `glither.flow`  (data-flow redaction on cycle boundaries)
```

## Core Concepts

<Plate section="A" title="Cycles" sub="named, typed, periodic patterns" num="1">

A **cycle** in BAZ.Luna is a named recurring pattern in an observation stream with:
- a **period** (estimated, with uncertainty bounds)
- a **phase** (current position in the cycle)
- an **amplitude** (current strength)
- a **confidence** score (how well the cycle fits recent data)

## DSL Syntax

BAZ.Luna adds a `baz.luna` dialect to the Glither comprehension language. Cycle phases
are first-class predicates:

```glither
#pragma dialect baz.luna ; fold accumulate

cycle intraday = market.intraday
cycle funding  = market.funding(period=8h, anchor=utc_midnight)

rule avoid_power_hour =
  bar
  | intraday.phase in [0.85, 1.0]              // last 15% of session
  | intraday.amplitude > 1.2                   // amplified cycle
  => signal PAUSE into holding
     on cycle intraday.reset into ready

rule funding_squeeze_alert =
  tick
  | funding.phase in [0.9, 1.0]               // near funding settlement
  | CycleRSI(funding) > 72                    // cycle-overbought
  | CycleMomentum > 0.4                       // still accelerating
  => signal WARNING into alerted
     after 30m into cleared (reason = funding_settled)
```

### Phase predicates

| Predicate | Semantics |
|---|---|
| `phase in [a, b]` | Current phase fraction within [a, b] (0=start, 1=end of cycle) |
| `cycle.reset` | Trigger: a new cycle period has begun |
| `cycle.peak` | Trigger: phase crossed the amplitude peak (phase ≈ 0.25 by default) |
| `CycleRSI(cycle) > x` | Cycle-relative RSI above threshold |
| `amplitude > x` | Current cycle amplitude above x (relative to 90d mean) |
| `confidence > x` | Cycle detection confidence above x (0–1) |

## Detection Methods

<Tabs defaultValue="autocorr">
<TabItem value="autocorr" label="Autocorrelation">

The primary detection method. For each candidate period T:

1. Compute the autocorrelation coefficient of the detrended series at lag T
2. Accept T as a cycle candidate if autocorrelation > threshold (default 0.6)
3. Rank candidates by coefficient magnitude — highest = primary cycle
4. Track phase by fitting a sine wave to the windowed series at period T

Efficient via the **Wiener–Khinchin theorem**: FFT → magnitude spectrum → peaks → lag.
Runs in O(N log N) per update window.

</TabItem>
<TabItem value="fft" label="FFT Spectrum">

For broad-spectrum cycle discovery (no prior on period):

1. FFT of the detrended, windowed observation series
2. Identify dominant frequency components (peaks in power spectrum)
3. Convert frequency → period; filter to [min_period, max_period] bounds
4. Each peak becomes a candidate cycle registered in the catalog

Best for discovering **unknown periods** in a new data stream. Runs once on
registration, then maintained incrementally.

</TabItem>
<TabItem value="hilbert" label="Hilbert Transform">

The Hilbert Transform produces an **analytic signal** — a complex representation
of the real input where the imaginary part is the 90°-shifted version. Phase is
then derived as `atan2(imag, real)`.

Used when the cycle is known (no discovery needed) and continuous phase tracking
is required. Zero-lag phase estimation with excellent noise rejection via the
Butterworth bandpass pre-filter centered on the known cycle frequency.

</TabItem>
</Tabs>

## Integration with BAZ.HFT

BAZ.Luna and BAZ.HFT communicate via a `glither.world` membrane link. A `baz.luna`
component exports phase signals; a `baz.hft` component imports them as ligands:

```glither
#pragma dialect glither.world ; fold accumulate

rule link_luna_to_hft =
  edge | donor.dialect == baz.luna
       | pour.export ~ /phase/
       | pier.dialect == baz.hft
       | guarantee.offer >= transport
  => link pour to pier into linked
```

Once linked, BAZ.HFT rules can reference `intraday.phase` directly in predicates —
no shared memory, only typed membrane exports.
